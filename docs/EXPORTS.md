# Admin exports

Every admin page that lists or reports data has one **Export** action: an icon button (download icon) at the top right of the data it exports. It opens one shared dialog; defaults are preselected, so one click exports, and every choice can be changed.

## What the dialog offers

- **Format:** CSV, Excel (.xlsx), PDF, PowerPoint (.pptx). Row caps per format: 50,000 for CSV and Excel, 5,000 for PDF, 500 for PowerPoint.
- **Rows (scope):** matching the current filters, rows on this page, selected rows, or everything. Page and selected only appear when the page's table publishes its row ids.
- **Date range:** for pages with a period.
- **Include:** page-specific include/exclude choices (channels, statuses, payment modes, revenue sources, and so on). Unticking an option recomputes the rows and totals without it.
- **Columns:** pick and reorder. Identifying columns (document number, date, GSTIN, store) come first by default.
- **Header & branding:** a header block for spreadsheets; for PDF a letterhead with the logo, a footer with page numbers and "generated by"; for PowerPoint a title slide and a summary slide. Every element can be switched off.
- **Presets:** the last choices per page per admin are re-applied on open (stored in `admin_export_presets`, name `''`); named presets can be saved and deleted.

## Architecture

| Piece | Where |
|---|---|
| Contract (client-safe types, defaults, validation) | `packages/store-core/src/lib/export/types.ts` |
| Definition contract | `packages/store-core/src/lib/export/define.ts` |
| Lists in the filter registry | `packages/store-core/src/lib/export/entity.ts` (automatic) + tweaks in `definitions/entities.ts` |
| Report definitions | `packages/store-core/src/lib/export/definitions/<area>.ts`, registered in `definitions/index.ts` |
| Pipeline (validate, tenant-bind, cap, render, audit, remember) | `packages/store-core/src/lib/export/pipeline.ts` |
| Renderers | `packages/store-core/src/lib/export/render/{csv,xlsx,pdf,pptx}.ts` (ExcelJS streaming, PDFKit + Noto Sans, pptxgenjs) |
| API | `admin-service/src/app/api/(admin)/admin/export/[key]/route.ts`: GET schema, POST count/export, PUT preset, DELETE preset |
| UI | `packages/store-core/src/components/admin/export/` (`ExportButton`, `ExportDialog`, `useExportRows`) |

Security: each request is held to the definition's read scope (`exportScope ?? scope`), rows come from the request's tenant DB (the tenant is captured and re-entered while the stream is pulled), and every export is written to the admin audit log.

## Adding Export to a page

**A list in the filter registry** (`packages/store-core/src/lib/filters/registry.ts`) already has an export: `<ListFilters … exportable />` shows the button. Tune it in `definitions/entities.ts` (column types, `id` columns, totals, `include` enum fields). For "this page" and "selected rows", give the page's `DataTable` an `exportKey` equal to the entity key (its `rowKey` must be the record id), or call `useExportRows(key, pageIds, selectedIds)`.

**Any other page** gets a report definition:

```ts
// definitions/<area>.ts
export const PL_EXPORT = defineExport({
  key: 'financial.pl',
  title: 'Profit & Loss',
  noun: 'Months',
  scope: 'financial:read',
  columns: [
    { key: 'month', label: 'Month', id: true },
    { key: 'revenue', label: 'Revenue', type: 'money', total: 'sum' },
  ],
  filters: [{ key: 'sources', label: 'Revenue sources', kind: 'multi', options: [...] }],
  dateRange: true,
  rangeFromQuery: q => ({ from: q.get('from') ?? undefined, to: q.get('to') ?? undefined }),
  sections: async ctx => {
    const report = await getPLReport(ctx.range.from!, ctx.range.to!) // the same function the page's API calls
    return [{ key: 'months', rows: report.monthly }]
  },
})
```

Rules that keep totals equal to the page:

- Call the **same function** the page's API route calls, with the same period and filters. Never re-implement the query.
- Apply include/exclude choices (`narrowed(filter, ctx.filters)` returns the ticked values, or null for "all") before computing totals, so they are recomputed.
- Totals: give columns `total: 'sum'` (or `'count'`/`'avg'`) and they are computed from the exported rows; or return a section's own `totals` row; add key figures as `summary`.
- A section without `columns` uses the columns the user picked; extra fixed tables (an HSN summary) pass their own `columns`.

Then put `<ExportButton exportKey="financial.pl" range={{ from, to }} />` at the top right of that data (the `PageHeader` `actions` slot, or the `Card` `action` slot when a page has several datasets).

**Data the page already holds** (every Insights drawer): the definition sets `clientRows: true` and the page passes `rows` to `ExportButton`; the pipeline validates them (plain values, at most 5,000 rows) into `ctx.rows`. Nothing is read from the DB, so `scope: ''` (any signed-in admin) is allowed only for these. `columnsFor(query)` / `titleFor(query)` let one definition serve pages whose columns differ (`definitions/insights.ts`).

A detail page passes its record in `query` (`product=<id>`, `form=<id>`, `job=<id>`); the definition validates it.
